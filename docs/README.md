# Documentation

These documents describe what DACTIVOS does, how it is built and why, and how it is secured and tested.

| Document                           | What it covers                                                                                           |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| [requirements.md](requirements.md) | What the system must do: roles, functional requirements, business rules and non-functional requirements. |
| [architecture.md](architecture.md) | How it is built: principles, request flow, project structure, data model, authentication, stack.        |
| [decisions/](decisions/README.md)  | Architecture decision records: context, decision, alternatives and consequences of each significant choice. |
| [security.md](security.md)         | Security measures with their tests, known limitations and a deployment checklist.                        |
| [testing.md](testing.md)           | Test levels, how to run them and which tests cover each requirement and rule.                            |
| [screenshots/](screenshots)        | Screenshots of a local installation with fictitious data, used in the README.                             |

The project history is in [CHANGELOG.md](../CHANGELOG.md).

**Identifiers.** Functional requirements (FR-1…), non-functional requirements (NFR-1…), business rules (R1…R13) and design decisions (D1…D13) have stable identifiers so that code, tests and ADRs can point to them.

**Language.** The documentation is in English; the user interface is in Spanish, so screen names and messages are quoted as they appear in the app.
